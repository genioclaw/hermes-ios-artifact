01 · Product

A private remote surface, not another chat service.

Hermes for iPhone connects Ren directly to a gateway he controls. It is designed for checking active work, continuing a conversation, sending context, and making deliberate approval decisions away from the Mac.

Contract boundary: this artifact does not invent Hermes endpoints or event fields. Authentication, session APIs, stream framing, attachments, approvals, pagination, and replay behavior must be validated against the live gateway before implementation.

Principles

  1. Secrets stay in Keychain. Content stays out of logs and notification previews.
  2. Tool activity is inspectable, while consequential work pauses for explicit approval.
  3. The app shows compact state instead of generating a bubble for every internal step.
  4. Network loss cannot silently change an action from pending to complete.
  5. The interface follows native accessibility, navigation, input, and security conventions.

Core jobs

  • Check what Hermes is doing without opening a laptop.
  • Resume a session and see live output as it arrives.
  • Send a photo, document, or voice note as working context.
  • Approve or deny an action with concrete scope and risk.
  • Lock the client and revoke its gateway token quickly.

User stories

  • As Ren, I can unlock with Face ID so casual phone access does not expose my agent.
  • I can see recent and active sessions and tell which one needs attention.
  • I can watch an answer stream and inspect sanitized tool detail without execution noise.
  • I can preview a photo, file, or voice recording before sending it.
  • I can understand an approval's actor, target, scope, and reversibility before deciding.
  • I can distinguish sending, sent, failed, and reconnecting states.
03 · Experience

Read the room. Then act.

First run

  1. Explain direct private connectivity and local secret storage.
  2. Enter an HTTPS gateway URL and choose the default profile.
  3. Write the token directly to Keychain through a secure field.
  4. Run a capability and connection check through the gateway adapter.
  5. Enroll Face ID as the local unlock requirement.

Returning use

The lock view reveals no conversations. After authentication, the session list sorts attention-needed and active work above history. Chat is a pushed detail view. An approval appears as a sheet and blocks only the related operation, not transcript reading.

Streaming and tools

The transcript shows connecting, streaming, waiting on a tool, or awaiting approval. Tool events collapse into one activity row with a human label, status, start time, and sanitized target. Raw payloads stay hidden.

Attachments and voice

Files use the system document picker. Photos use selected-only access. Voice capture includes elapsed time, level, stop, replay, delete, and send. Upload errors remain attached to the draft instead of disappearing in a toast.

04 · Requirements

Behavior that can be tested.

Authentication and connection

  • Accept only https:// gateway URLs outside local debug builds.
  • Store credentials only in a device-only Keychain item.
  • Gate credential retrieval with LocalAuthentication.
  • Support token replacement, revocation guidance, logout, and local erasure.
  • Separate reachability, TLS, authentication, protocol mismatch, and server errors without echoing secrets.

Sessions and chat

  • List, create, open, and resume sessions through the adapter.
  • Stream output and reconcile authoritative state after reconnect.
  • Render a safe subset of Markdown, code, links, lists, and tables.
  • Preserve local drafts without caching the token or raw tool payloads.
  • Retry only when duplication is impossible or a verified idempotency mechanism exists.

Approvals and media

  • Normalize queued, running, succeeded, failed, and approval-required tool events.
  • Require a deliberate tap to approve or deny. Silence and timeouts never approve.
  • Re-authenticate configured high-impact approvals.
  • Read gateway state before marking an approval complete.
  • Preview and remove attachments; show upload progress and durable failure state.

Quality requirements

  • No secrets in UserDefaults, SwiftData, logs, crash metadata, analytics, pasteboard, or notification bodies.
  • Session cache appears within one second; streamed text renders as transport delivers it.
  • Reconnect does not reorder messages or duplicate approval decisions.
  • Support VoiceOver, accessibility text sizes, reduced motion, sufficient contrast, and non-color cues.
  • Transport and wire schema remain isolated from views and domain models.

Adapter boundary

protocol HermesClient: Sendable {
  func capabilities() async throws -> GatewayCapabilities
  func sessions() async throws -> [SessionSummary]
  func createSession(profile: String) async throws -> SessionID
  func events(for session: SessionID)
    -> AsyncThrowingStream<HermesEvent, Error>
  func send(_ draft: OutboundDraft, to session: SessionID)
    async throws -> MessageReceipt
  func decide(_ decision: ApprovalDecision)
    async throws -> ApprovalReceipt
}

These types describe app needs, not confirmed server names. The discovery spike maps verified gateway behavior into them.

Background reality

iOS will suspend a direct socket. MVP reconnects on foreground and queries authoritative state before resuming live events. If reliable remote alerts become necessary, a small private push relay receives only opaque event identifiers. The phone fetches details after unlock.

06 · Security

Treat the mobile token as high privilege.

The preferred route is direct HTTPS over Tailscale or another private network. Standard TLS validation remains mandatory. Certificate pinning is optional and needs a rotation and recovery plan.

Abuse cases

  • Stolen unlocked phone: short auto-lock, Face ID on return, optional re-authentication for approvals, protected local data.
  • Token in backup: device-only Keychain accessibility; credentials excluded from backups.
  • Malicious notification: no message body and no approval action in the notification.
  • Prompt-induced action: approval detail comes from normalized trusted fields, not model-authored prose alone.
  • Log leakage: allowlisted fields and central redaction; never write headers or raw event dumps.
  • Duplicate send: use a verified idempotency key or reconcile before retry.
  • Snapshot exposure: obscure the app-switcher snapshot and privacy-mark sensitive views where practical.

The gateway should issue a scoped, revocable mobile credential instead of reusing an administrator secret. If that capability does not exist, the first release must state the exposure and make revocation easy.

07 · Delivery

Prove the contract before building the surface.

Discovery spike

  1. Inventory supported authentication and capability discovery.
  2. Capture list, create, send, stream, tool, approval, completion, cancel, and reconnect lifecycles.
  3. Validate framing, heartbeat, ordering, replay cursor, and terminal events for WebSocket or SSE.
  4. Test attachment upload and voice-note representation.
  5. Determine pagination, errors, idempotency, versioning, and token revocation.
  6. Build a fixture gateway from sanitized captures for deterministic tests.

Open questions

  • Can the gateway issue a scoped and revocable mobile credential?
  • Are approvals durable and queryable after reconnect?
  • Does event replay expose a cursor or sequence number?
  • Which attachment limits and MIME types are advertised?
  • Is a voice note sent as audio, transcribed, or both?
  • Which tool fields are safe and useful to display?
  • Is foreground reconciliation enough for MVP notifications?
08 · Acceptance

The MVP is done when these are true.

  1. A fresh install configures an HTTPS gateway without writing a token outside Keychain.
  2. Face ID or device passcode is required according to the chosen lock policy.
  3. Ren can list, create, resume, and search sessions.
  4. A reply streams progressively and settles into authoritative final state.
  5. Routine tools stay compact; sanitized detail is available on demand.
  6. Consequential work pauses for explicit approval or denial. Timeout and backgrounding cannot approve.
  7. The app reads gateway state before reporting approval completion.
  8. Photos, files, and voice notes can be previewed, sent, safely retried, and removed locally.
  9. Airplane mode, route change, gateway restart, and app suspension do not create duplicate messages or false success.
  10. Notifications, snapshots, logs, cache, and diagnostics reveal no token or sensitive message text by default.
  11. VoiceOver, accessibility text sizes, reduced motion, both appearances, and 44-point targets pass manual review.
  12. Settings can replace or revoke the credential, lock immediately, and erase local data.
  13. The binary contains no analytics SDK or vendor relay.
  14. Contract tests cover implemented events and fail clearly on incompatible versions.
09 · Release

Private pilot first.

  1. Develop against the fixture gateway.
  2. Test on physical devices over a private network with a dedicated revocable token.
  3. Review Keychain policy, transport, redaction, approval integrity, and local storage.
  4. Run a small TestFlight pilot for Ren. Keep crash reporting off unless a reviewed redacted path is added.
  5. Fix pilot failures and freeze the first adapter contract.
  6. Use private distribution first. Broader release waits for safe gateway onboarding and revocation.

Rollback: expire the mobile token, remove the TestFlight build, and erase app data. Gateway access must never depend on the phone client.
